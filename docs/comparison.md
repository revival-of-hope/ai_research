# 论文实验结果对照（UC08）

该功能在 `/comparison` 提供一份论文、一份本地运行摘要的字段对照。复用账号、资料库和模型预设；通用快速问答和深度研究接口保持不变。

## 使用与接口

1. 在“论文结果对照”页面直接上传论文（可提取文字的 PDF、DOCX、TXT 或 Markdown），也可以选择资料库中已经保存的论文。
2. 上传本地训练或评估得到的指标摘要（TXT、Markdown、CSV、DOCX 或文本 PDF）。如果只有控制台日志或自己记下的指标，可以直接粘贴在页面的“实验摘要”文本框并保存为 Markdown 文件。不需要上传模型权重、实验代码或整个数据集。
3. 确认两份不同资料已选中，输入目标指标（如 `top-1 error`、`mIoU`；多实验行时注明目标模型与表格行），选择已有 Responses 模型预设，点击“生成候选对照”。
4. 进入复核工作台：左侧是本次论文与运行摘要，右侧是十字段对照表。点击字段查看两侧原文摘录、完整文本块和状态，修正候选值；如引用不准确，可在对应来源内搜索文本块、更换文本块并编辑摘录。保存时服务端会验证文本块属于本次所选来源，且摘录出现在该文本块中。逐项选择“确认此字段”或“标记未解决”，每次复核都会保存。
5. 所有字段复核后确认摘要。已确认的记录只读，可从“最近的对照记录”重新打开。

上传资料由现有 `POST /api/documents` 接口保存到当前账户的资料库，并可跨对照重复使用；页面中的两种上传方式共用此接口。生成候选对照时，后端立即保存一份 `pending` 记录；最终确认改为 `confirmed`。刷新页面后，可分别从已保存资料和历史对照继续操作。文件只有在状态为 `ready` 时才能用于对照。

示例运行摘要（格式不固定，内容仅用于说明，数值为虚构）：

```text
模型：ResNet-50
数据集：ImageNet
数据划分：validation
评估方式：10-crop
指标：top-1 error
结果：24.10%
随机种子：42
```

候选抽取的总时限为 120 秒；生成期间可取消请求。目标描述上限 120 字，前端会提示超限而不是静默截断。

所有接口都需要当前用户登录；比较记录、资料和模型预设按用户隔离。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/comparisons` | 当前用户的历史对照摘要 |
| `POST /api/comparisons` | 建立候选对照，输入 `paper_document_id`、`run_document_id`、`provider_id`、`metric` |
| `GET /api/comparisons/{id}` | 字段、证据、状态及复核信息 |
| `GET /api/comparisons/{id}/evidence/{side}/{key}` | 根据当前用户所属记录、来源侧和字段读取已上传文档的完整原文文本片段 |
| `GET /api/comparisons/{id}/source-chunks/{side}?q=...` | 只在本次已选来源内列出候选片段，或按词语搜索最多 12 个片段 |
| `PATCH /api/comparisons/{id}` | `updates` 中逐字段提交值、`paper_source`/`run_source` 引用、`review_status` 和 `note`；引用必须来自对应来源；`confirm: true` 完成确认 |

两份资料分别进行结构化抽取，并发执行且共用 120 秒上限。模型返回空的字段列表时，会在剩余时限内重试一次；返回了候选但原文摘录无法核实时不重试。失败时分别标出论文侧或运行摘要侧；诊断日志只记录错误类型，不保存模型原文、密钥或用户内容。曾有 R01 免费模型请求返回 502，当前尚不能确定根因。

后端将两个文档分别提供给一个结构化字段提取 Agent；它只能读取当前选择的候选文本块，没有执行代码或联网搜索工具。每份资料最多使用 12 个文本块，每个块最多 3000 个字符（当前分块大小为 1800，因此该上限不会截断文本）。论文与运行摘要使用不同的指令：论文侧必须把数值绑定到用户指定的模型行与表格组，运行摘要侧只忠实转录摘要实际写明的内容，即使与目标模型、划分或指标不同。

候选字段必须包含与所选文本块匹配的原文摘录。缺失、引用错误或无法证实的字段输出 `unknown`；可证实的字段值按规范化后的文字作确定性比较，输出 `aligned` 或 `mismatch`。数值按十进制值比较，百分数单位的 `%` 与 `percent` 视为一致，不自动换算不同数值尺度。新增 `training` 字段区分直接训练、预训练和微调：比较的是**预训练来源**而不是措辞，`ImageNet-1K trained models` 与 `ImageNet-1K only (no ImageNet-22K pretraining)` 判为 `aligned`，而论文行来自 1K 直接训练、运行摘要报告 22K 预训练时判为 `mismatch`；被否定的表述（`no ImageNet-22K pretraining`）不计作预训练。两侧描述详略不同且无法判断时保留 `unknown`。随机种子字段为可选信息；数值差异不构成实验因果解释。比较摘要确认之前，每个字段必须经过人工复核。

字段语义按以下规则规范化后再比较：

| 字段 | 规则 |
| --- | --- |
| `metric` | `top-1 err.` 与 `top-1 error`、`Top-1 Acc.` 与 `top-1 accuracy` 视为同一指标；开头的 `ImageNet`/`IN-1K` 等数据集限定词忽略。仅写 `Top 1` 的表头只有在同一侧摘录出现 `accuracy`/`error` 定义时才解释为对应指标，否则保持 `unknown`。`top-1` 与 `top-5` 始终是不同指标。 |
| `unit` | 只比较计量单位本身：`%`、`percent`、`percentage` 归一为 percent，`%, 10-crop testing` 这类附带评估约定的写法同样归一为 percent。一侧没有可识别的计量单位时不判为冲突，保留 `unknown`。 |
| `dataset` / `split` | `dataset` 不含划分词，`ImageNet validation` 归为 `ImageNet`；`50k validation images` 归为 `validation`。`the test set` 这类非数据集名称不作为数据集。 |
| `preprocessing` | 按可比属性比较：裁剪方式（`single-crop`、`10-crop` 等）与输入分辨率（`224 x 224`、`224× 224` 以及 PDF 中上标被压平的 `2242` 视为同一分辨率）。属性冲突判为 `mismatch`；两侧必须描述同一组属性，任一侧缺少裁剪方式或分辨率时保留 `unknown`，不因共享其中一个属性就判为一致。 |
| `value` | 只有 `metric` 为 `aligned` 时才比较数值；指标为 `mismatch` 或任一侧 unknown 时数值一律 `unknown`，避免把不同指标（或指标不明）的数值当作可比条件下的性能差异。人工复核保存时同样重新计算该依赖，事后修改数值不会让它变成可比。 |

论文侧若模型漏掉条件字段，服务端只从**引用了目标行的分块**补齐：表格标题、列标题、表格分组标题，或该行自身的单元格。相邻分块按数据库中的 `ordinal`（论文原文顺序）判断，不使用候选排序列表里的相邻位置。

所有论文侧的确定性补齐（`dataset`、`split`、`preprocessing`、`unit`、`metric`、`model`、`training`）共用同一份取证范围：**引用了结果值的那一行所在分块**、表格标题分块，以及它们在论文中前后各 2 个原文块。窗口只由这一行决定；模型或指标在别的分块被引用时不会扩大窗口。**模型名也只在这个范围内检索**——同一模型在别的章节或别的表格里再次出现时，那一段的裁剪方式、数据划分和单位都不属于目标实验，不会被取用。没有引用到结果值时，任何条件都不补齐。`dataset` 不从任意正文推断，只来自目标行的表格标题；`unit` 只来自标题中的 `%`、数值所在行的 `%`，或同一范围内的出现。结果行所在分块中，如果行之前已经出现一个明确的表格标题（单独成行的 `Table N.`），就由它判定所属表格：编号与请求不符时直接拒绝补齐，不会跳过它去改用相邻分块里编号恰好相符的标题。正文中的交叉引用（如 `as shown in Table 5.`）不是标题，不参与该判定。表格标题按编号校验：请求里写明 `Table 3`（或 `Tables 3 and 4`）时，只有编号相符的标题才能用来补 `dataset`、`split`、`unit`；相邻位置若只有别的表格标题（例如 `Table 9`），一律不采用，字段保持 `unknown`。请求指定了多个表号而相邻标题恰好都命中时，无法判断目标行属于哪一张，同样保留 `unknown`。请求没有写明表号时仍按相邻标题处理，因为没有可校验的编号。补齐值同样是逐字摘录并绑定该文本块。运行摘要侧只从形如 `Model: ...`、`Value: 74.7%` 的显式标签行补齐模型漏掉的字段，已给出的候选不会被覆盖。补齐失败时字段保持 `unknown`。

## 部署与限制

部署现有服务前执行 `cd backend && uv run --frozen alembic upgrade head`，或沿用已有的迁移流程。新增迁移为 `0010_comparison`；它只新增 `comparison_record`，不修改原有会话及上传资料表。

当前来源定位是数据库的文本块 ID 与逐字摘录。研究者可从复核界面打开对应文档的解析文本片段；摘录能在原始 PDF 的**唯一一页**逐字匹配时，额外显示 PDF 页码，否则不猜测。尚不提供段落、表格行列坐标和 OCR，也不能保证模型选择了正确实验行。

旧九字段记录保持原样可读；缺少训练条件的旧记录不能据此宣称所有核心条件一致。原来九字段金标准的评估与新增十字段评估必须分别统计，不可直接混算。候选抽取的准确性、不同模型的 Responses 兼容性、费用和端到端延迟需要真实材料与模型测试。资料删除后，已经保存的对照摘要仍保留之前的摘录，但对应原文文本块可能不再可读取。对照记录一经确认即不可再修改。
