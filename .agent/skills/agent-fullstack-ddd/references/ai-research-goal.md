# AI Research 重写 Goal

## 目标

对 revival-of-hope/ai_research 进行可运行的前后端重写。后端采用 DDD 与 Pydantic AI，保留 ddgs 搜索，实现受控动态子智能体。前端保留浅色、slate、宽屏聊天和已有组件气质，依据竞品研究优化研究工作台。保留账户、加密模型预设、资料上传/RAG、持久化会话、用量与管理功能。

## 执行与验收

1. **基线与调研**：完整阅读代码/需求文档；保存仓库来源与已知行为、竞品官方资料和 skill 来源。验收：有明确的保留清单和界面决策。
2. **可复用技能**：本文件所属 skill 写入 `.agent/skills`，安装并阅读官方 Pydantic AI skill。验收：skill 可验证且本次按其流程实施。
3. **领域设计与契约**：设计研究任务聚合、证据、任务/Agent 状态和预算；划分 domain、repo、uow、service、infrastructure、api；明确流事件和迁移。验收：领域不依赖基础设施，事务与所有权规则有测试。
4. **后端重写**：账户、模型、资料、会话和研究服务迁入新架构；用 Pydantic AI supervisor/researcher/reviewer/synthesizer 实现真实工具委派和动态派生；ddgs 保持唯一搜索实现。验收：成功、上游错误、预算耗尽、取消与数据隔离路径可验证。
5. **前端重写**：新研究入口、历史、资料选择、研究深度/模型设置、Agent 过程、引用/来源、停止与恢复；接通后端。验收：响应式界面、明确加载/空/错态和无障碍交互，类型检查与构建通过。
6. **集成与交付**：验证数据库迁移、API/流契约、持久化、测试、容器配置；更新 README/docs。验收：提供完整本地代码、检查结果与真实凭据/环境限制，不声称未经验证的线上成功。

## 分工

主 Agent 负责技能、架构契约、集成与最终验证；subagents 分别负责原项目/竞品审计、后端独立模块、前端实现和后续审查。避免多个 Agent 同时修改同一文件。
