# Agent 全栈开发与重构

把自然语言需求变成可交付、可验证的多步 Goal。先理解现有仓库、相关文档和运行配置，再实施；不得把完整重写缩减为架构建议或空目录。

## 工作流程

1. 审阅 README、架构/API 文档、需求文件、现有页面、数据库迁移和测试。记录用户必须保留的行为、视觉设计和兼容约束。把推断写入项目计划，缺少非关键偏好时自行合理决定。
2. 生成有依赖顺序与验收条件的 Goal/实施计划。对可独立的调研、界面实现、测试审计派生 subagent，明确文件所有权、接口契约和交接要求；主 Agent 负责集成验证。
3. 检索高度相关的公开 skill，优先框架官方来源；审阅后下载到用户指定的本地 skill 目录，记录来源与许可证，实际读取并复用相关部分。技能是开发指引，不代表运行时依赖。
4. 比较主流同类产品的官方界面/流程资料。保留既有颜色、布局气质和组件语言，优化任务入口、研究计划、过程反馈、来源引用、历史和错误恢复。不要只换主题而遗漏功能。
5. 按 DDD 划分 domain、application/service、repo 接口、uow 接口、infrastructure 和 HTTP 适配层。domain 不依赖 ORM、HTTP、LLM 或框架；service 编排业务；repo 处理查询/存储；uow 定义提交、回滚与会话生命周期。避免只给旧模块换文件夹名。
6. Agent 默认使用 Pydantic AI 的依赖注入、类型化输出和原生工具委派；支持监督者、研究者、审阅者及按任务派生子智能体。明确并发数、派生深度、调用/搜索预算、超时和取消传播；联网搜索使用 ddgs。阻塞搜索放工作线程；记录可展示的步骤与证据，不伪造来源或暴露私密推理。
7. 先明确 HTTP/流事件契约再并行开发前后端。鉴权和资源所有权在服务边界检查；密钥仅在服务端使用；文件处理、错误响应、流断连和数据库事务要有真实行为。
8. 用确定性模型/搜索替身验证研究路径与失败路径，检查租户隔离、提交回滚、派生限制、取消、引用与用量；运行后端检查、前端类型检查/构建和可行的浏览器交互。明确区分已通过检查和需要真实模型凭据的验证。
9. 更新安装、迁移、架构和 API 文档，交付可运行代码、精确的运行步骤和验证记录。未经用户要求，不改变远程分支、部署目标或发布数据。
