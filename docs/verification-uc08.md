## 真实模型调用

真实请求使用配置中标为免费的 Agents-A1 Responses 接口，顺序执行，没有并发调用。共完成 2 组论文/摘要对照、4 次成功的 Responses 请求。随后进行 1 次较严格结构约束的兼容性探测：服务返回 HTTP 200，但响应未通过当时的九字段验证，未生成对照记录。该约束已移除，缺失字段由系统保留为 `unknown`。

### 字段抽取

人工依据论文及对应合成摘要预先标注每侧 8 个可支持字段：`dataset`、`version`、`split`、`model`、`preprocessing`、`metric`、`unit`、`value`。论文和摘要未报告随机种子，因此不把 `seed` 计入分母。按字段键和字段值计分，缺失字段及字段放错位置计为错误；`%`/`percent` 和 `40.7`/`40.7%` 按已实现的窄范围规则视为等价。

| 样例 | 论文侧 | 摘要侧 | 合计 |
| --- | ---: | ---: | ---: |
| `00-match.md` | 2/8 | 8/8 | 10/16 |
| `05-match-canonical.md` | 2/8 | 8/8 | 10/16 |
| 总计 | 4/16 | 16/16 | **20/32（62.5%）** |

两组使用了不同版本的抽取指令；样例量很小，且来自同一篇论文，结果仅作初步观察。论文侧的主要问题是字段缺漏，以及把 `ILSVRC-2012` 放入数据集字段而未拆出数据集版本。

逐组结果：`00-match.md` 的论文侧输出 `dataset=ILSVRC-2012`、`model=1 CNN`、`value=40.7%`，其余支持字段缺失；运行摘要侧八个字段均匹配样例。`05-match-canonical.md` 的论文侧只输出 `unit=%`、`value=40.7`，其余支持字段缺失；运行摘要侧八个字段均匹配样例。

### 证据定位与误判

- 成功记录中共采纳 21 个字段候选；21 个都通过了所选文本块 ID、逐字摘录及字段值包含关系校验。这个数字只描述通过校验并被保存的候选；系统不会保存被过滤的原始候选，因此不代表模型全部原始引用的精确率。定位粒度是文本块，不是 PDF 页码或表格单元格坐标。
- 两组模型输出按修正后的规则回放，出现 3 个自动 `aligned` 字段（数值及百分数单位），人工核对均与来源一致：观察到错误 `aligned` 为 0/3。样本太少，不能据此估计一般场景的误判率。
- 浏览器流程中，第一组数据集字段由人工根据摘要摘录修订后确认；刷新页面后重新打开，字段值、引文、状态和确认结果均已持久化。第二组保留为待复核记录。

### 耗时与用量

耗时取自每次 Responses HTTP 请求的实际计时。每组对照顺序调用模型两次，因此将两次请求耗时相加作为近似整组模型请求耗时，不含页面加载及人工操作时间。

| 样例/请求 | 两次请求耗时合计 |
| --- | ---: |
| `00-match.md` | 112.593 秒 |
| `05-match-canonical.md` | 98.478 秒 |
| 两组平均 | 105.536 秒 |

两组均低于 120 秒，但样本量不足以估计 p95。成功的 4 次 Responses 请求合计返回 24,581 tokens；兼容性探测另返回 9,246 tokens，五次请求合计 33,827 tokens。服务未对三次请求返回输入/输出 token 拆分，也未返回实际费用；模型配置标记为免费，因此本次没有付费调用，也无法据此估算美元费用。

## 发现并修复

1. 并发字段编辑可能基于旧状态覆盖另一请求刚确认的记录。隔离 PostgreSQL 实测复现后，为编辑路径增加行锁和刷新读取，并增加并发回归测试。
2. 两个顺序抽取请求最长可分别等待 90 秒；新增 120 秒整组时限、超时错误响应和浏览器取消入口。客户端断开时后端取消抽取，未保存半成品。
3. 百分数字段的格式差异会将同一数值误报为不一致。对数值字段增加十进制规范化，对单位字段统一 `%` 和 `percent`；不同尺度仍保持不一致。
4. 实际模型会省略不确定字段。抽取提示允许省略缺失字段，由领域层将缺失项显示为 `unknown`，不要求模型填造空字段。
5. PostgreSQL 迁移测试在新增 `0010_comparison` 后仍断言旧版本号。现已更新断言，并检查新表在降级后移除。

## 官方 DeepSeek 批量评估（2026-11-03）

使用 DeepSeek 官方 Responses 接口，对 hw2/uc08-test-data 中 5 篇论文和 20 份合成运行摘要执行全部 20 组。目标描述包含金标准中的目标模型和表格上下文；每组顺序抽取论文与摘要，共 40 个请求。批量调用直接使用项目的候选片段排序、extract_evidence 和确定性比较逻辑；评测完成后将输出从结果 JSON 导入隔离测试账户的 20 条待复核记录，并把来源摘录重新映射到对应已上传文件的实际文本块，没有再次调用模型。

- 20/20 组完成，40/40 个 Responses 请求返回 HTTP 200，没有抽取异常。
- 九字段状态与金标准匹配 123/180（68.33%）。70 个预期为 mismatch 或 unknown 的字段中，错误 aligned 为 0。
- 217 个经本地片段/摘录校验后保留的候选均有可支持摘录；该数值不代表原始模型引用的精确率。
- 单次请求 n=40，平均 16.264 秒，中位数 16.208 秒，nearest-rank p95 为 18.378 秒，范围 14.200–20.758 秒；每组论文与摘要请求合计平均 32.527 秒、中位数 32.727 秒、p95 为 34.736 秒，范围 29.234–39.136 秒。
- 返回 173,576 个输入 token（其中 129,024 个缓存命中）和 10,621 个输出 token。按 [DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing/) 的非高峰单价估算约 USD 0.013442；该值是费用估算，不是账户账单。

字段状态匹配率仍受论文侧漏提、字段类别混淆和多行表格选择影响：例如 R01 把 “the test set” 放入 dataset；M01 把 “Top 1” 与 “top-1 accuracy” 判为不同指标；S03 把 single-crop 评估方式放入 unit。逐例字段、状态和证据摘录已保存在独立评测结果记录中。这些运行摘要是合成测试数据，不代表真实训练结果。MoDian 网关的另一次 R01 论文侧请求返回 HTTP 429，未完成对照，也未计入上述结果。
