## 需求覆盖

- 官方搜索：按 DeepSeek 2026-10-17 发布的 Search 文档调用 `/v1/tools/search`；OpenAI 使用 Responses `web_search`。搜索开关、密钥快照、错误脱敏、拒绝重定向、取消和超时均有模拟传输测试。
- 快速问答：真实 SDK 对 MockTransport 只发送一次 Responses 模型请求；HTTP 入口测试明确禁止构造研究 Runner，核对没有计划、Agent 或进度事件，`agents=0`、`requests=1`。
- 快速搜索：OpenAI 内置搜索随同一次模型请求执行；DeepSeek 独立 Search 后发送一次模型请求，支持 Flash。关闭联网不发送搜索。
- 推理：快速请求和 Pydantic AI 研究请求均验证 `medium`；旧客户端的推理字段不能覆盖该默认。前端没有推理开关、强度选择或对应请求状态。
- 研究设置：组件渲染和浏览器均验证固定展开在深度研究栏内、位于输入框上方；快速模式隐藏研究设置与过程卡片。
- 持久化：两种模式均保存消息、来源、用量和运行状态；历史读取补齐模式，保留账户、预设、资料所有权和旧会话。
- 用量：深度研究的 OpenAI 搜索额外模型请求和 token 用量计入共享预算，预算不足时不继续发送请求。
- 来源：OpenAI 引用按原始 offset 绑定对应句段；不将同一段混合摘要复制给所有 URL。无可靠引用位置时留空摘要，不伪造页面文本。

## 连接与流边界

覆盖连接失败、响应正文中断、SSE 读取错误、截断事件、取消、未完成响应、上游 HTTP 错误脱敏和完成后尾流报错。

收到有效完成事件后，后端停止读取上游流，前端取消并释放响应 reader。测试先证明旧的前端实现会在完成后的错误或永不结束的尾流上失败，再确认修复后通过。完成前错误和业务回调异常没有被吞掉。

## 浏览器联调

使用独立 SQLite、默认开发管理员及虚构密钥；上游模型、搜索均为进程内模拟，无真实收费调用。

1. 验证深度研究设置醒目展示，并把协作规模改为 4、派生深度改为 2。
2. 快速问答隐藏研究设置，返回普通回答和来源；模拟服务记录确认为一个 medium 模型请求，未创建研究团队。
3. 刷新后从历史打开快速问答，仍恢复快速模式，不出现研究过程卡片。
4. 深度研究执行计划、研究者和来源流程，仍保留用户选定的协作设置。
5. 故意停止本次启动的 Vite 服务，再发送请求，实际复现浏览器连接失败。页面显示明确中文说明和恢复操作，没有自动重复 POST；恢复服务后重新发送成功。
